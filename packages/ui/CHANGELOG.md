# @parselabllc/ui

## 0.1.1

### Patch Changes

- 950d236: Fix `HTMLElement`/`customElements` not actually being polyfilled in Node — `@lit-labs/ssr-dom-shim` only auto-patches `globalThis.Event`/`CustomEvent`, not `HTMLElement`/`customElements` as the previous comment assumed, so any SSR framework that evaluates `@parselabllc/ui`/`@parselabllc/ui/react` on the server (e.g. Remix) crashed with `HTMLElement is not defined`. Also fixes the package's own build silently tree-shaking that shim away, because `sideEffects` in `package.json` didn't cover `src/**/*.ts` (used while building the package itself) or `dist/esm/react.js` (the `/react` entry point, for downstream consumers).
- badb2ef: Redesign `<p-button>`'s default look to match Shopify Polaris's own default button — light-mode colors, 8px radius, Inter typography, and padding are Polaris's actual `@shopify/polaris-tokens` values (primary now near-black `#303030` rather than indigo, secondary is white with a subtle border rather than filled gray, critical uses Polaris's red). Also fixes `--p-color-border`/`--p-color-text` not being visible against dark backgrounds — `variant="tertiary"`'s border and text were effectively invisible whenever the page didn't happen to match the component's light-mode fallback colors, since nothing actually loaded `@parselabllc/ui/tokens.css`. Dark-mode values (not part of Polaris, which has no official dark theme) are this package's own adaptation, and now apply for an explicit `data-theme="dark"` host attribute too, not just OS `prefers-color-scheme`.

  `:active` (pressed/click) now shows a distinct inset box-shadow per variant, on top of the existing background/text-color change — previously pressing a button only changed color, with no shadow feedback at all.

  Follow-up pass against Shopify's real `<s-button>` compiled CSS (not just `@shopify/polaris-tokens`) for exact fidelity: primary's subtle top-gloss gradient, the precise multi-layer bevel shadows for every variant/tone/state (default, hover, and the pressed-in look are each genuinely different now, not one shadow reused), a 1px "press" shift of the label separate from the button's own border/shadow (tertiary/plain opt out, matching Shopify), per-variant disabled colors (previously a blanket `opacity: 0.6`), and a `loading` state that now hides the label via `color: transparent` (keeping the button's width stable, per this package's own docs) with the spinner absolutely centered on top, instead of rendering spinner and label side by side.

  Fixes `variant="secondary"` (the default) always showing a visibly thick, always-on gray border: it had a real CSS `border` _and_ an inset box-shadow ring simulating a border at the same edge, doubling up. There's no real `border` anywhere on the button now — every variant's border (or lack of one) comes purely from `box-shadow`, matching `<s-button>` exactly, which is also how hover/active/disabled correctly turn it off or change it by only swapping `--_shadow` rather than needing a separate `border-color` override too.
